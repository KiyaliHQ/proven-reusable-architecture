= Vue d'ensemble architecturale — Registre PRA
:page-title: Vue d'ensemble architecturale

Le Registre PRA (Proven Reusable Architecture) est la plateforme centralisée de la Banque Nationale pour cataloguer, partager et gouverner les patrons architecturaux validés en production.

Ce document présente l'architecture complète de la plateforme, ses flux, ses agents IA et sa gouvernance.

== 1. Vue d'ensemble de la plateforme

Le registre suit un modèle *Git-centric* : le repository GitHub est la source de vérité unique. Deux cibles de publication sont alimentées automatiquement à chaque merge.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam defaultFontName "Segoe UI"
skinparam defaultFontSize 13
skinparam shadowing false
skinparam roundCorner 10
skinparam ArrowColor #333333

actor "Architectes\n(~200)" as arch

package "GitHub Repository" as repo #c8102e {
}

rectangle "GitHub Actions\n(CI/CD automatique)" as ci #333333

rectangle "GitHub Pages\n(Dashboard filtrable)" as ghp #2563eb
rectangle "Confluence\n(Wiki entreprise)" as conf #2563eb

arch -down-> repo : Contribuer\n(Pull Request)
repo -down-> ci : Merge sur main
ci -right-> ghp : Build\nAsciidoctor + PlantUML
ci -left-> conf : Publish\nDocker Publisher
arch -right-> ghp : Consulter
arch -left-> conf : Consulter

note bottom of repo
  Source de vérité unique
  PRAs · Guides · Templates
  Config · Agents IA
end note
@enduml
----

*Principe clé* : Git est le seul point d'écriture. GitHub Pages et Confluence sont des vues en lecture seule, régénérées à chaque merge.

== 3. Architecture du contenu

Le contenu est organisé en deux scopes avec une hiérarchie claire. Les 7 archétypes sont communs à tous les niveaux.

----

skinparam defaultFontName "Segoe UI"
skinparam defaultFontSize 13
skinparam shadowing false
skinparam roundCorner 10
skinparam ArrowColor #333333

  BackgroundColor #ffffff
  BorderColor #d1d5db
}

rectangle "Registre PRA" as root #c8102e

rectangle "Bank-Wide\n(Transversal)" as bw #e8f5e9
rectangle "Domain-Wide\n(Par domaine)" as dw #e3f2fd

rectangle "7 Archétypes" as arch #fff5e1 {
  rectangle "Intégration" as a1 #ffffff
  rectangle "Application" as a2 #ffffff
  rectangle "Data" as a3 #ffffff
  rectangle "Sécurité" as a4 #ffffff
  rectangle "Technology" as a5 #ffffff
  rectangle "DevOps" as a6 #ffffff
  rectangle "Business" as a7 #ffffff
}

rectangle "Domaines" as domains #e3f2fd {
  rectangle "Particuliers" as d1 #ffffff
  rectangle "Entreprises" as d2 #ffffff
  rectangle "Gestion Patrimoine" as d3 #ffffff
  rectangle "Carte" as d4 #ffffff
  rectangle "..." as d5 #f5f5f5
}

root -down-> bw
root -down-> dw
bw -down-> arch : organisé par
dw -down-> domains : organisé par
domains -down-> arch : puis par archétype

note bottom of arch
  Chaque PRA contient :
  · Fiche signalétique (métadonnées)
  · Contexte, Architecture, ADR
  · Implémentation, Proven-in-use

  Statut = métadonnée, pas un dossier
end note
@enduml
----

*Point important* : Le statut (`operationalizing`, `operationalized`, `deprecated`) est une métadonnée du PRA, pas un élément de la hiérarchie de dossiers.

== 4. Agents IA — Architecture

Deux agents IA permettent aux architectes d'interagir avec le registre en langage naturel, directement depuis VS Code ou Claude Code. Les deux sont *config-driven* et *structure-agnostic*.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam defaultFontName "Segoe UI"
skinparam defaultFontSize 12
skinparam shadowing false
skinparam ArrowColor #333333
skinparam sequence {
  ParticipantBackgroundColor #ffffff
  ParticipantBorderColor #d1d5db
  LifeLineBackgroundColor #f9fafb
}

actor "Architecte" as arch
participant "PRA Explorer" as explorer #c8102e
participant "PRA Guide" as guide #2563eb
database "Registre\n(config + contenu)" as reg

== Trouver un pattern ==

arch -> explorer : "Je dois intégrer\nSalesforce pour Entreprises"
explorer -> reg : Lire config + scanner PRAs
explorer --> arch : "Salesforce FSC disponible\n2 proven-in-use, score 8/10"

== Comprendre le process ==

arch -> guide : "Comment soumettre un PRA ?"
guide -> reg : Lire guides + docs
guide --> arch : "1. Copier template\n2. Documenter FR+EN\n3. Soumettre PR"

@enduml
----

== 5. Gouvernance

Deux niveaux de gouvernance reflètent les deux scopes du registre. Les CODEOWNERS GitHub automatisent l'assignation des reviewers.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam defaultFontName "Segoe UI"
skinparam defaultFontSize 12
skinparam shadowing false
skinparam roundCorner 10
skinparam ArrowColor #333333

rectangle "Bank-Wide" as bw #c8102e {
  rectangle "Comité Architectes Experts\n5-7 experts cross-domaines\n\nReview : 2-4 semaines\n2 approbations\n3+ proven-in-use" as bw_rules #ffffff
}

rectangle "Domain-Wide" as dw #2563eb {
  rectangle "Comité par domaine\n3-5 architectes\n\nReview : 5-10 jours\n1+ proven-in-use" as dw_rules #ffffff
}

rectangle "CODEOWNERS (automatique)" as co #fff5e1 {
  rectangle "bank-wide/ → @comité-experts\nparticuliers/ → @comité-particuliers\nentreprises/ → @comité-entreprises\nbuild/ → @équipe-plateforme" as co_rules #ffffff
}

bw -[hidden]right-> dw
bw -down-> co
dw -down-> co

note bottom of co
  GitHub assigne automatiquement
  les reviewers selon le fichier modifié
end note
@enduml
----

== 6. Cycle de vie d'un PRA

Chaque PRA suit un cycle de vie clair, de la contribution initiale jusqu'à la dépréciation éventuelle.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam defaultFontName "Segoe UI"
skinparam defaultFontSize 13
skinparam shadowing false
skinparam ArrowColor #333333
skinparam state {
  BackgroundColor #ffffff
  BorderColor #d1d5db
}

[*] --> Contribution

state "Contribution" as contrib #fce4ec : PR + Review\nCODEOWNERS

contrib --> Operationalizing : Approuvé

state "Operationalizing" as op #e3f2fd : 1+ proven-in-use\nCollecte de retours

op --> Operationalized : Critères atteints\n(3+ bank-wide)

state "Operationalized" as done #e8f5e9 : Pattern recommandé\nMaintenance active

done --> Deprecated : Remplacé ou obsolète

state "Deprecated" as dep #ffebee : Non recommandé\nPlan de migration

dep --> [*]
@enduml
----

== 7. Pipeline CI/CD

À chaque merge sur `main`, deux jobs parallèles publient le contenu en moins de 5 minutes.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam defaultFontName "Segoe UI"
skinparam defaultFontSize 12
skinparam shadowing false
skinparam ArrowColor #333333
skinparam sequence {
  ParticipantBackgroundColor #ffffff
  ParticipantBorderColor #d1d5db
}

actor "Architecte" as arch
participant "GitHub" as gh #333333
participant "GitHub Actions" as ci #c8102e
participant "GitHub Pages" as ghp #2563eb
participant "Confluence" as conf #2563eb

arch -> gh : Merge PR sur main
gh -> ci : Déclenche CI/CD

ci -> ghp : Job 1 : Asciidoctor\n+ PlantUML → HTML
ci -> conf : Job 2 : Docker\nPublisher → Pages

ghp --> arch : Site à jour (< 2 min)
conf --> arch : Pages à jour (< 3 min)

note over ci
  Deux jobs parallèles
  Zéro intervention manuelle
end note
@enduml
----

*Résultat* : Un seul merge sur `main` met à jour les deux plateformes simultanément. Zéro intervention manuelle.
