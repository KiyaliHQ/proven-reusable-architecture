= Architectural Overview — PRA Registry
:page-title: Architectural Overview
:keywords: architecture, overview, platform, ci-cd, governance
:pra-hide-meta: true

The PRA Registry (Proven Reusable Architecture) is Banque Nationale's centralized platform for cataloguing, sharing and governing architectural patterns validated in production.

This document presents the complete platform architecture, its flows, AI agents and governance.

== 1. Platform Overview

The registry follows a *Git-centric* model: the GitHub repository is the single source of truth. Two publication targets are fed automatically.

[plantuml]
----
@startuml

skinparam defaultFontSize 13

  RoundCorner 15

  BackgroundColor #f8f9fa

  rectangle "PRAs (.adoc)" as pras #fff

  rectangle "Templates" as templates #fff
  rectangle "AI Agents" as agents #fff
  rectangle "CI/CD Config" as cicd_conf #fff
}

  rectangle "Filterable dashboard" as dash #fff

  rectangle "PRA Space" as confSpace #fff
  rectangle "FR/EN Hierarchy" as confTree #fff

actor "Architects" as arch #6c757d

repo -down-> cicd : merge to main
cicd -down-> ghpages : Job 1: Asciidoctor\n+ PlantUML

@enduml
----

*Key principle*: Git is the only write point. GitHub Pages and Confluence are read-only views, regenerated on every merge.

== 4. AI Agents — Architecture

Two AI agents allow architects to interact with the registry in natural language, directly from VS Code or Claude Code.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam participant {
  RoundCorner 10
}

actor "Architect" as arch
participant "PRA Explorer" as explorer #c8102e
database "content/pras/" as pras
database "pra-registry.config.yml" as config

== PRA Explorer: Find a pattern ==

arch -> explorer : "I need to integrate\nSalesforce in the\ncorporate domain"
explorer -> config : Step 0: Read config\n(structure, archetypes, domains)
explorer -> pras : Step 1: Explore\ncontent/pras/{lang}/
explorer -> pras : Step 2-3: Search by\ntags, archetype, content
explorer -> arch : Step 4: Recommendation\n"Salesforce FSC (Domain-Wide)\n2 proven-in-use, satisfaction 8/10"

@enduml
----

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam participant {
  RoundCorner 10
}

actor "Architect" as arch
participant "PRA Guide" as guide #1a73e8
database "content/guides/" as guides
database "docs/" as docs
database "pra-registry.config.yml" as config

== PRA Guide: Process question ==

arch -> guide : "How do I submit\na PRA?"
guide -> config : Step 0: Read config
guide -> guides : Step 1: Explore\ncontent/guides/{lang}/
guide -> docs : Step 2-3: Read\nrelevant documentation
guide -> arch : Step 4: Structured answer\n"1. Copy template\n2. Document FR+EN\n3. Submit PR\n4. CODEOWNERS review"

@enduml
----

Both agents are *config-driven* (`pra-registry.config.yml`) and *structure-agnostic*: they dynamically discover content without hardcoded paths.

== 6. PRA Lifecycle

Each PRA follows a clear lifecycle, from initial contribution to eventual deprecation.

[plantuml]
----
@startuml

  RoundCorner 15
  BackgroundColor #fff

state Contribution #fce4ec {
  state "Branch + Documentation\nFR + EN" as contrib
  state "PR Review\n(CI + CODEOWNERS)" as review
  contrib --> review
}

Contribution --> Operationalizing : Approved

state Operationalizing #e3f2fd {
  state "1+ proven-in-use" as op1
  state "Collecting experience\nfeedback" as feedback
  op1 --> feedback
}

Operationalizing --> Operationalized : 3+ proven-in-use\n(bank-wide)\nor domain criteria

state Operationalized #e8f5e9 {
  state "Recommended pattern\nfor new projects" as recommended
  state "Active maintenance\n(< 6 months since update)" as maintained
  recommended --> maintained
}

Operationalized --> Deprecated : Replaced or obsolete

state Deprecated #ffebee {
  state "Not recommended\nfor new projects" as not_rec
  state "Migration plan\ndocumented" as migration
  not_rec --> migration
}

Deprecated --> [*]
@enduml
----

== 7. CI/CD Pipeline

On every merge to `main`, two parallel jobs publish content in under 5 minutes.

[plantuml]
----
@startuml
skinparam backgroundColor transparent
skinparam participant {
  RoundCorner 10
}

actor "Architect" as arch
participant "GitHub" as gh #333
participant "GitHub Actions" as gha #c8102e
participant "GitHub Pages" as ghp #1a73e8
participant "Confluence Cloud" as conf #1a73e8

arch -> gh : Merge PR to main
gh -> gha : Trigger workflows\n(push event)

== Job 1: GitHub Pages (parallel) ==
gha -> gha : Install Java 17\n+ Asciidoctor + PlantUML
gha -> gha : generate-dashboard.sh\n(index/catalogue)
gha -> gha : build.sh\n(.adoc -> HTML + PNG)
gha -> ghp : Deploy\n(upload artifact)

== Job 2: Confluence (parallel) ==
gha -> gha : publish-confluence.sh
gha -> conf : Create/find\nhierarchy pages\n(REST API)
gha -> conf : Sanitize + publish\n14 subdirectories\n(Docker Publisher)

ghp -> arch : Site updated\n(< 2 min)
conf -> arch : Pages updated\n(< 3 min)
@enduml
----

*Result*: A single merge to `main` updates both platforms simultaneously. Zero manual intervention.
