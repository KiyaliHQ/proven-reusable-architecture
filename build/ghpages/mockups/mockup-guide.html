Comment contribuer un PRA

Ce guide vous accompagne dans la soumission d'un nouveau PRA (Proven Reusable Architecture) au registre. Le processus est conçu pour être simple tout en garantissant la qualité et la réutilisabilité des architectures partagées.

Tout architecte ou développeur senior ayant validé un pattern en production peut soumettre un PRA. La contribution est encouragée et reconnue par la table de gouvernance.

Prérequis

  • Accès au dépôt GitHub — Vous devez avoir un accès en écriture au repository proven-reusable-architecture
  • Pattern validé en production — Au moins 1 implémentation en production (pour le statut Candidate)
  • Documentation complète — Overview, contexte, architecture, ADRs, implémentation, retours d'expérience
  • Git — Connaissances de base en git (clone, branch, commit, PR)
  • AsciiDoc — Familiarité avec la syntaxe AsciiDoc pour la rédaction du contenu

Étapes de contribution

1

Cloner le dépôt et créer une branche

Commencez par cloner le dépôt et créer une branche dédiée à votre contribution :

# Cloner le dépôt git clone https://github.com/BanqueNationale/proven-reusable-architecture.git cd proven-reusable-architecture # Créer une branche de contribution git checkout -b pra/api-gateway-pattern
2

Créer le fichier PRA

Utilisez le template fourni et placez votre fichier dans le bon répertoire selon le scope et la catégorie :

# Copier le template cp templates/pra-template-fr.adoc \ content/pras/fr/domain-wide/particuliers/api-gateway-pattern.adoc # Structure attendue content/pras/ fr/ bank-wide/ # Patterns transversaux domain-wide/ # Patterns par domaine particuliers/ entreprises/ gestion-patrimoine/
⚠️ Important : Utilisez un fichier plat (mon-pra.adoc), pas un dossier (mon-pra/page.adoc). C'est une convention architecturale du registre (ADR-003).
3

Remplir les attributs AsciiDoc

Chaque PRA commence par un bloc d'attributs AsciiDoc en en-tête du fichier .adoc :

= API Gateway Test Pattern :pra-name: API Gateway Test Pattern :pra-archetype: technology // technology|integration|security|business :pra-status: operationalizing // operationalizing|operationalized|deprecated :pra-scope: domain-wide // bank-wide|domain-wide :pra-origin: particuliers // domaine ou pratique source :pra-tags: api, gateway, microservices, kong :pra-created: 2025-12-03 :pra-updated: 2025-12-03 :pra-proven-count: 1
4

Rédiger la documentation complète

Documentez toutes les sections requises avec du contenu réaliste et utile (pas de Lorem Ipsum) :

  • Overview — Description concise du pattern (2-3 phrases)
  • Contexte — Quand utiliser / ne pas utiliser
  • Architecture — Diagramme, stack technique, composants
  • ADRs — Décisions d'architecture avec alternatives considérées
  • Implémentation — Guide pas-à-pas avec code blocks
  • Retours d'expérience — Au moins 1 proven-in-use documenté
  • Limitations — Contraintes et risques connus
  • Références — Liens vers documentation externe
5

Créer la version anglaise

Le registre est bilingue. Créez la version anglaise dans le répertoire correspondant :

# Copier et traduire pour la version anglaise cp content/pras/fr/domain-wide/particuliers/api-gateway-pattern.adoc \ content/pras/en/domain-wide/particuliers/api-gateway-pattern.adoc # Modifier le fichier anglais : title, description, contenu
6

Soumettre la Pull Request

Commitez, poussez et ouvrez une PR pour revue par la table de gouvernance :

git add content/pras/ git commit -m "feat(pra): add API Gateway Test Pattern" git push origin pra/api-gateway-pattern # Ouvrir une PR sur GitHub # Taguer : @pra-governance pour la revue

Critères de qualité

La table de gouvernance évalue chaque soumission selon les critères suivants :

Critère Exigence Obligatoire
Proven-in-use Au moins 1 implémentation documentée Oui
Contexte clair Quand utiliser ET ne pas utiliser Oui
ADRs documentés Au moins 1 ADR avec alternatives Oui
Code d'implémentation Exemples de code fonctionnels Oui
Bilingue FR/EN Les deux versions linguistiques Oui
Diagramme d'architecture Représentation visuelle de l'architecture Recommandé
Limitations documentées Contraintes et risques connus Recommandé

Questions fréquentes

Combien de temps prend la revue d'un PRA?

La table de gouvernance se réunit toutes les 2 semaines. Comptez 2 à 4 semaines entre la soumission et l'approbation, selon la complexité et les retours demandés.

Mon pattern n'a qu'une seule implémentation. Puis-je le soumettre?

Oui! Une seule implémentation en production suffit pour le statut Candidate. Le passage au statut Approved nécessite 3 implémentations pour les PRAs Bank-Wide, et 1 pour les Domain-Wide.

Qui peut promouvoir un PRA de Domain-Wide à Bank-Wide?

La promotion est initiée par la table de gouvernance lorsqu'un PRA Domain-Wide atteint 3 implémentations prouvées dans des contextes différents. Le processus est documenté dans le guide de promotion.

Puis-je modifier un PRA existant?

Oui. Suivez le même processus de PR. N'oubliez pas de mettre à jour le champ updated_at et d'ajouter une entrée dans proven_in_use si vous documentez une nouvelle implémentation.

Où trouver de l'aide?

Rejoignez le canal #pra-registry sur Slack, ou contactez la table de gouvernance à pra-governance@company.com.
